# ADR-0002: ตัดสินใจเลือก Typescript ในการพัฒนา

- **Status:** Accepted
- **Date:** 2026-10-04
- **Deciders:** Jakapong Chan-o ( PM )


## Context

วิธีการเขียนโค๊ด ที่แตกต่างกันของ Developer และที่ผ่านมา โค๊ดค่อนข้าง maintain ยาก และเกิด error บ่อย



## Decision

ตัดสินใจ นำ typescript มาใช้ 
เพื่อให้ developer code ได้อย่างเป็นระบบมากยิ่งขึ้น และง่ายต่อการพัฒนาต่อกัน



กติกาที่ทีมต้องทำตาม:
- กำหนดรูปแบบของข้อมูลให้ชัดเจน
- ทุกๆครั้งที่มีการพัฒนา module ใดๆ ต้องมีการเช็ค eslint ทุกครั้งไม่ว่าจะเป็น frontend หรือ backend ว่าถูกต้องตามหลัก typescript หรือไม่ ก่อนจะส่งมอบ module นั้นๆ

หมายเหตุการตัดสินใจด้านสถาปัตยกรรม:

- ADR ฉบับนี้เคยบันทึกว่าไม่เลือก Microservices แต่ถูกแทนที่โดย [ADR-0001](0001-record-architecture-decisions.md)
  ซึ่งอัปเดตและอนุมัติให้เริ่มด้วย Microservices ในวันที่ 2026-10-04
- การเลือก TypeScript ใน ADR นี้ยังคงเดิม

## Consequences

**ข้อดี**
- รูปแบบการเขียนจะเป็นไปในแนวทางเดียวกัน

**ข้อเสีย**
- Dev ต้องมีความรู้เรี่อง typescipt
